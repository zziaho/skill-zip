# 도로명주소 API

행정안전부를 위해 운영하는 주소기반산업지원서비스(business.juso.go.kr)의 주소 API를 호출할 때 참조하는 자료입니다. 2026-11-06에 저장한 사이트의 API 페이지와 같은 날 내려받은 가이드 및 샘플을 기준으로 검증했습니다(가이드 PDF의 날짜는 PDF 생성일 기준이며, 검색 유형이 2025-12, 팝업 유형이 2026-07입니다).

**범위**: API 9개입니다. 도로명주소 검색, 팝업, 모바일 팝업, 영문주소 검색과 팝업, 좌표제공 검색과 팝업, 상세주소 검색과 팝업입니다. 지도 API(지도제공 검색, 팝업)와 내려받는 주소 데이터베이스, 공간 데이터는 다루지 않으므로, 추측하지 말고 다루지 않는다고 밝힙니다.

이 자료에 대한 사이트의 이용약관은 확인하지 않았습니다. 이 스킬은 자료를 그대로 옮기지 않고 요약하고 바로잡았습니다.

## 사용 방법

1. 아래 표로 API 유형을 고릅니다. 유형에 따라 신청할 승인키가 달라집니다.
2. 해당 API의 참조 파일을 읽고, 이 파일의 규칙(승인키, 차단, 보안)도 **반드시** 읽습니다.
3. **개발**할 때는 공식 샘플이 아니라 이 스킬의 바로잡은 예시에서 시작합니다.
4. juso 샘플에서 복사한 코드를 **검토**할 때는 아래 "공식 샘플의 문제"와 참조 파일의 표로 대조합니다.

## 표기 규칙

| 강도 | 의미 | 검토할 때 보고하는 방식 |
|------|------|--------------------------|
| `R` | 자료가 규칙으로 서술했거나, 어기면 오류 코드가 반환되고 IP가 차단되거나 서비스가 중지되는 규칙입니다 | 위반 |
| `G` | 자료가 권장 사항으로 서술한 규칙입니다 | 권장 사항 |
| `D` | 자료끼리 내용이 다르거나, 자료에 내용이 없거나, 공식 샘플이 안전하지 않은 부분에 대한 이 스킬의 판단입니다. 이유를 옆에 적어 둡니다 | 권장 사항. juso 가이드의 범위를 넘어선다는 점을 함께 알립니다 |

- **자료끼리 내용이 다른 곳이 많습니다.** API 페이지, 가이드 PDF, 내려받는 샘플이 필드 이름(`lnbrMnnm`을 `InbrMnnm`으로 표기), 필수 여부, `resultType`의 의미, 엔드포인트 URL, 오류 메시지에서 서로 다릅니다. 이 스킬의 표는 바로잡은 것이며, 각 참조 파일에 무엇을 어떤 근거로 바로잡았는지 적어 두었습니다.
- 필드 이름은 대소문자를 구분합니다. 지번 필드는 소문자 L로 시작합니다(`lnbr`).

## API 유형 선택

| 상황 | 유형 | 이유 |
|------|------|------|
| 우편 주소가 필요한 대부분의 폼 | **팝업**(모바일 웹은 모바일 팝업) | juso가 검색 화면, 검색어 처리, 페이지 나누기, 상세주소 단계를 제공합니다. 작성할 코드가 가장 적습니다 |
| 검색이 자체 화면의 일부여야 하는 경우(인라인 목록, 자동 완성, 앱 화면) | 서버에서 호출하는 **검색** | 모든 것을 직접 제어합니다. 목록, 페이지 나누기, 상세주소 입력을 직접 만듭니다 |
| 좌표도 필요한 경우 | 좌표 팝업, 또는 검색 후 좌표 검색 | `coordinate-api_ko.md` |
| 아파트 호 선택 | `useDetailAddr=Y`를 지정한 팝업, 또는 상세주소 검색 | `detail-address-api_ko.md` |

## 승인키(`confmKey`)

| 규칙 | 강도 |
|------|------|
| business.juso.go.kr에서 주소정보 자료제공 → 주소정보 API 연계로 이동한 뒤, API 목록에서 해당 API의 신청하기를 눌러 신청합니다. API(도로명주소, 영문주소, 좌표제공, 상세주소)**와** 유형(검색, 팝업, 모바일 팝업)을 선택합니다 | `R` |
| **시스템 하나에 키 하나를 URL이나 IP 기준으로 발급합니다.** 키는 발급받은 URL이나 IP에서만 동작합니다. 사이트나 애플리케이션마다 각각 키가 필요하며, 키를 여러 사이트가 공유하면 서비스가 중지될 수 있습니다. 도메인이 여러 개(예: `sub.test.co.kr`, `new.test.co.kr`)라면 활용시스템 리스트 양식을 첨부해 URL이나 IP마다 키를 발급받습니다 | `R` |
| **팝업용 키와 검색용 키는 서로 바꿔 쓸 수 없습니다.** 바꿔 쓰면 `E0001`(승인되지 않은 KEY)이 반환됩니다 | `R` |
| 개발승인키는 본인 확인 없이 바로 발급되며 **만료**됩니다(`E0014`). 가이드는 기간을 밝히지 않습니다. 운영 승인키를 신청하려면 본인 확인이 필요합니다 | `R` |
| 개발승인키가 만료되어 서비스가 중지되지 않도록, 서비스를 공개하기 전에 운영 승인키를 신청합니다 | `D` |
| `TESTJUSOGOKR`은 가이드의 샘플에서 쓰는 테스트 키입니다 | `G` |
| 신청 내역은 마이페이지 → API 인증키 관리에서 확인하고 수정합니다 | `G` |
| 검색용 키는 코드나 페이지가 아니라 서버 설정에 보관하고, 검색 API는 서버에서 호출합니다(`secure-coding` 23) | `D` |
| 팝업용 키는 반드시 페이지에 노출됩니다. 키를 보호하는 수단은 등록한 URL이나 IP이므로, 범위가 넓은 URL이 아니라 정확한 URL을 등록합니다 | `D` |

## 모든 API에 적용되는 규칙

| 규칙 | 강도 |
|------|------|
| `https://business.juso.go.kr/addrlink/…`를 사용합니다. 검색 페이지는 TLS 1.2를 쓸 수 없는 런타임을 위해 `http://`를 허용하지만 사용하지 않습니다. 키와 사용자의 주소가 평문으로 전송됩니다(`secure-coding` SR2-8). 행정망 시스템은 고객센터(1588-0061)에 URL을 문의합니다 | `D` |
| **SQL 예약어나 `<` `>` `=` `%`가 들어 있는 검색어는 `E0013`을 반환할 뿐 아니라 서비스의 보안 장비가 호출한 IP를 차단할 수 있습니다.** 호출하기 전에 검색어를 정제하고 사용자에게 메시지를 보여 줍니다(`search-api_ko.md`의 "검색어 필터") | `R` |
| 서버에서도 검색어를 검사하고, 입력을 몰래 고치지 말고 메시지와 함께 거부합니다 | `D` |
| **주소 API는 모의 해킹에서 제외합니다.** 점검자의 IP가 차단될 수 있다고 가이드가 여러 번 경고합니다 | `R` |
| 자동 취약점 스캔에서도 제외합니다 | `D` |
| 좌표 API는 짧은 시간에 호출이 너무 많으면 `E0007`을 반환하고, 검색 API는 9,000건을 넘겨 페이지를 넘길 수 없습니다(`E0015`) | `R` |
| 어떤 API도 반복문으로 대량 호출하지 않습니다. 주소를 입력받을 때 호출하고 결과를 저장합니다 | `D` |
| 결과를 사용하기 전에 `errorCode`를 확인합니다. `0`이 성공입니다. 오류 코드는 **API마다 다릅니다**(`E0005`는 검색 API에서 "검색어 없음"이고 좌표 API와 상세주소 API에서는 "`buldMnnm` 누락"입니다). API별로 따로 대응시킵니다 | `D` |
| 코드 필드는 문자열로 저장합니다. `zipNo`와 `emdNo`는 앞자리가 0이고, `bdMgtSn`(25자리)은 64비트 정수에 들어가지 않습니다 | `D` |
| 사용자의 브라우저에서 돌아오는 주소 값(팝업 콜백, 폼 필드)은 사용자 입력으로 취급하고, 다른 입력과 똑같이 검증하고 이스케이프합니다 | `D` |

## 공식 샘플의 문제

대부분의 프로젝트가 사이트의 JSP, PHP, ASP, Java 샘플을 복사합니다. 이 샘플에는 다음 문제가 있습니다(`D`. 자세한 내용과 수정 방법은 참조 파일에 있습니다).

| 문제 | 위치 | 수정 방법 | `secure-coding` |
|------|------|-----------|-----------------|
| 전달받은 값을 이스케이프하지 않고 JavaScript 문자열에 기록합니다: `opener.jusoCallBack("<%=roadFullAddr%>", …)`(returnUrl 페이지의 반사형 XSS) | 모든 팝업 샘플: `jusoPopup.jsp`, `.php`, `.asp` | HTML로 이스케이프해서 DOM에서 읽거나 JSON으로 인코딩합니다(`popup-api_ko.md`) | 4 |
| API 결과를 HTML로 이어 붙여 `.html(...)`로 삽입합니다 | 검색, 좌표, 상세주소 샘플 | `textContent`, `.text()`, `new Option()` | 4 |
| 키를 브라우저에서 받거나(`req.getParameter("confmKey")`) 화면에 보이는 입력란에 둡니다 | 검색, 좌표, 상세주소 프록시 샘플 | 서버 설정 | 23 |
| 검색어만 URL 인코딩하고 다른 파라미터는 그대로 이어 붙입니다. `admCd =` 오타가 있고, 상세주소 샘플이 좌표 URL을 호출합니다 | 프록시 컨트롤러 | 모든 파라미터를 인코딩하고 검증합니다 | |
| 타임아웃이 없고, 오류가 나면 스트림을 닫지 않습니다 | 프록시 컨트롤러 | 타임아웃과 try-with-resources | 40 |
| 검색어 필터가 단어 안의 `OR`를 제거하고(`KOREA` → `KEA`) `[` `]`를 놓칩니다 | `checkSearchedWord` | 단어 전체를 비교하고, 고쳐 쓰지 말고 거부합니다 | |
| `document.domain`, IE 신뢰할 수 있는 사이트와 호환성 보기 안내 | 팝업 샘플과 가이드 | 더 이상 쓰지 않습니다. `popup-api_ko.md`의 배포 시 주의할 점을 참조합니다 | |

## 개발할 때

1. API 유형을 정하고, 시스템의 URL이나 IP마다 키를 신청합니다(개발승인키부터 신청합니다).
2. 팝업: returnUrl 페이지를 폼과 같은 출처에 두고, CSRF 필터와 로그인 필터에서 제외하며, 출력 이스케이프를 적용해 작성합니다(`popup-api_ko.md`).
3. 검색: 키를 보관하는 서버 엔드포인트를 추가해 검색어와 페이지를 검증하고, 모든 파라미터를 인코딩하고, 타임아웃과 호출 제한을 설정하고, JSON을 반환합니다(`search-api_ko.md`).
4. `roadAddrPart1`, 상세주소, `roadAddrPart2`, `zipNo`, `bdMgtSn`을 따로 저장하고, 화면에 표시하는 문자열은 이 값들로 조합합니다.
5. 공개하기 전에 운영 승인키로 바꾸고, 보안 점검자에게 juso 엔드포인트를 제외하도록 알립니다.

## 검토할 때

1. returnUrl 페이지와, `<script>` 안에서 `<%= %>`, `<?= ?>`, 요청 값의 문자열 이어 붙이기를 사용하는 곳을 찾습니다.
2. `confmKey`가 어디에서 오는지, 검색 API를 브라우저에서 호출하는지 확인합니다.
3. 프록시 컨트롤러를 확인합니다: 인코딩, 검증, 타임아웃, 콘텐츠 타입, 호출 제한.
4. 필드 이름을 바로잡은 표와 대조하고(`InbrMnnm`이 아니라 `lnbrMnnm`), 오류 처리를 해당 API의 코드 표와 대조합니다.
5. 호출 전에 검색어를 필터링하는지, 그 필터가 영문 도로명을 깨뜨리지 않는지 확인합니다.

## 관련 스킬

- `secure-coding`: 보안약점 4번(XSS), 23번(하드코드된 중요정보), 40번(자원 해제), 설계 기준 SR1-5(웹 서비스 요청 및 결과 검증)와 SR2-8(중요정보 전송)
- `krds`: `references/form-patterns_ko.md`의 주소 행(개인 식별 정보 입력): 주소 검색을 여는 버튼, 그 버튼으로 채우는 읽기 전용 우편번호, 별도의 상세주소 필드. 해당 표는 그 문서에서 KRDS의 범위를 넘어선다고 표시되어 있습니다(`D`)
- `egovframe`: 프록시를 전자정부 표준프레임워크로 만들고 키를 `globals.properties`에 보관한다면, 해당 스킬의 `references/code-inspection_ko.md`가 설명하는 대로 암호화 서비스로 키를 암호화하고 저장소에 두지 않습니다. `D`: 상위 호출은 컨트롤러가 아니라 서비스 클래스에 둡니다
