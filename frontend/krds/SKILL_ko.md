# KRDS (범정부 UI/UX 디자인시스템)

행정안전부가 www.krds.go.kr에 공개한 한국 정부의 UI/UX 디자인시스템 KRDS로 웹 폼을 만들고 검토할 때 참조하는 자료입니다. 2026-11-06에 저장한 KRDS 사이트를 기준으로 검증했습니다. Figma 라이브러리 v1.0.0과 HTML Component Kit v1.0.1(페이지 최초 등록일 2025-01-15)이며, 태그 v1.0.3과 맥락적 도움말 v1.0.4 갱신분을 포함합니다.

**현재 범위는 입력 폼입니다.** 이 스킬은 조회표에 나열한 폼 관련 기본 패턴, 컴포넌트, 서비스 패턴을 다룹니다. 내비게이션, 레이아웃, 아이덴티티(헤더, 푸터), 디자인 토큰 등 KRDS의 다른 영역은 아직 포함하지 않았으므로, 추측하지 말고 포함하지 않았다고 밝힙니다.

KRDS 자료는 공공누리 제1유형(KOGL Type 1)으로 제공되며, 상업적 이용과 변형이 가능하고 출처를 표시해야 합니다. KRDS가 제안하는 출처 문구는 다음과 같습니다. 본 저작물은 행정안전부에서 2024년 작성하여 공공누리 제1유형으로 개방한 '범정부 UI/UX 디자인시스템(KRDS)'을 이용하였으며, 해당 저작물은 'KRDS 디자인시스템 홈페이지(www.krds.go.kr)'에서 무료로 다운받으실 수 있습니다.

**특정 공공 웹사이트에 KRDS 적용이 의무인지는 이 스킬에서 확인하지 않았습니다.** 의무가 있다고 단정하지 말고, 고객에게 프로젝트의 요구사항을 물어봅니다.

## 사용 방법

1. 먼저 폼의 유형을 정합니다(`references/form-patterns_ko.md`의 "입력 폼" 참조). 단일 화면, 모달, 단계별 중 하나입니다.
2. 조회표에서 작업에 해당하는 항목을 찾고, 그 항목이 가리키는 파일**만** 읽습니다.
3. **개발**할 때는 패턴의 규칙을 따르고, 이어서 화면에 있는 각 컴포넌트의 규칙을 따릅니다. 각 컴포넌트의 **마크업** 부분에 있는 KRDS 클래스와 이 스킬의 바로잡은 예시를 사용합니다.
4. **검토**할 때는 화면에 있는 각 패턴과 컴포넌트의 **규칙** 표를 확인하고, 신청 서비스라면 `references/application-flow_ko.md`의 체크리스트도 확인합니다.

## 표기 규칙

| 강도 | 의미 | 검토할 때 보고하는 방식 |
|------|------|--------------------------|
| `R` | KRDS가 요구 사항으로 서술한 규칙입니다("~해야 한다", "~안 된다", "~하지 않는다", "반드시"). 서비스 패턴 체크리스트의 필수 항목이거나, KWCAG 2.2 항목과 연결된 접근성 규칙도 해당합니다(KRDS가 권장이나 고려한다로 서술했다면 `G`입니다) | 위반 |
| `G` | KRDS가 일반적인 방식으로 서술한 규칙입니다("~한다", "권장", "~하는 것이 좋다"). 권장/우수 체크리스트 항목도 해당합니다 | 권장 사항 |
| `D` | KRDS에 내용이 없거나, 일관되지 않거나, KRDS의 예시 코드가 KRDS의 규칙을 어기는 부분에 대한 이 스킬의 판단입니다. 이유를 옆에 적어 둡니다 | 권장 사항. KRDS의 범위를 넘어선다는 점을 함께 알립니다 |

- 보고할 때는 KRDS 페이지 이름과 규칙을 함께 적습니다. 예를 들어 "KRDS 텍스트 입력 필드: 플레이스홀더가 레이블이나 도움말의 대체 수단으로 사용되어서는 안 된다"처럼 씁니다.
- KRDS의 접근성 규칙은 KWCAG 2.2 항목을 이름으로만 인용합니다. 이 스킬은 항목 번호를 덧붙입니다(예: 레이블 제공 = 7.3.2). `accessibility` 스킬을 설치했다면, 그 스킬의 `references/cross-reference_ko.md`에서 WCAG와의 대응까지 확인할 수 있습니다.
- **KRDS의 예시 코드는 KRDS 자신의 규칙을 자주 어기거나 권장하는 내용을 빠뜨립니다.** 도움말을 `aria-describedby`로 연결하지 않거나, 그룹에 `fieldset`/`legend`를 쓰지 않거나, 규칙이 요구하는 곳에 `autocomplete`가 없거나, 버튼이 들어 있는 팝오버에 `role="tooltip"`을 붙이는 경우가 있습니다. 예시 마크업이 아니라 규칙을 따릅니다. 이 스킬의 예시는 바로잡은 것입니다.

## 공통 필드 마크업

KRDS는 모든 필드를 같은 블록으로 구성합니다.

| 블록 | 클래스 | 비고 |
|------|--------|------|
| 필드 그룹 | `.form-group` | 레이블 하나, 컨트롤 하나, 도움말은 선택 |
| 레이블 영역 | `.form-tit` | `<label for>`를 넣습니다. 그룹이라면 `<legend>`를 대신 씁니다(`D`) |
| 컨트롤 영역 | `.form-conts` | 상태에 따라 `.is-error`, `.is-success`, `.is-information`을 추가합니다 |
| 도움말 | `p.form-hint` | `aria-describedby`로 연결합니다(`D`: KRDS 예시는 연결하지 않습니다) |
| 메시지 | `p.form-hint-invalid`, `.form-hint-success`, `.form-hint-information` | 오류 문구는 `form-hint-invalid`에 넣습니다 |

바로잡은 필드입니다(`D`: KRDS의 예시에는 `aria-describedby`, `aria-invalid`, `autocomplete`가 없습니다).

```html
<div class="form-group">
  <div class="form-tit"><label for="user_name">이름</label></div>
  <div class="form-conts is-error">
    <input type="text" id="user_name" class="krds-input" autocomplete="name"
           aria-describedby="user_name_hint user_name_error" aria-invalid="true">
  </div>
  <p class="form-hint" id="user_name_hint">개명한 경우 회원 정보에서 이름을 변경한 후 신청할 수 있습니다.</p>
  <p class="form-hint-invalid" id="user_name_error">이름을 입력해 주세요.</p>
</div>
```

## 개발할 때

1. 폼 유형을 정하고, 제목(`h2`부터 `h6`)으로 섹션을 나누며, 기본적으로 한 열로 배치합니다.
2. 각 필드에는 컴포넌트 파일의 "적합한 경우/부적합한 경우" 항목을 보고 컴포넌트를 고릅니다.
3. 모든 컨트롤에 눈에 보이는 `<label>`(그룹은 `<legend>`)을 달고, 도움말은 `aria-describedby`로 연결하며, 개인정보 필드에는 `autocomplete`를 지정합니다.
4. 필수와 선택 필드를 한 가지 일관된 방식으로 표시하고, 클라이언트에서 검증하되 서버에서도 반드시 검증하며, 오류가 발생해도 사용자가 입력한 값을 유지합니다.
5. 제출 버튼은 액션 그룹의 오른쪽 끝에 두고, 요청이 진행되는 동안에는 비활성화합니다.

## 검토할 때

1. 폼 유형과 화면에 있는 모든 패턴과 컴포넌트를 파악합니다.
2. KWCAG 항목을 포함해 각 항목을 **규칙** 표와 대조합니다. 이어서 **키보드** 표로 키보드 동작을 확인합니다.
3. 신청 서비스라면 `references/application-flow_ko.md`의 체크리스트도 확인하고, 필수 항목을 먼저 보고합니다.
4. 결과를 묶어서 적습니다. `R` 위반을 먼저 적고, 그다음에 `G`와 `D` 권장 사항을 적습니다. 항목마다 해당 요소, KRDS 페이지와 규칙, 수정 방법을 함께 적습니다.

## 관련 스킬

- `accessibility`: 여기서 인용한 모든 접근성 규칙의 KWCAG 2.2와 WCAG 상세 내용
- `secure-coding`: 보안약점 6번(파일 업로드), 15번(히든 필드와 클라이언트 값), 29번(지속되는 쿠키, "로그인 정보 저장"), 33번(로그인 시도 횟수 제한), 설계 기준 SR2-7(중요 데이터 저장). KRDS와 secure-coding이 충돌하는 것처럼 보이는 경우(비밀번호 자동 완성)는 `references/application-flow_ko.md`의 "로그인 정보 입력"을 참조합니다
