# 입력 컴포넌트

값을 입력하는 KRDS 컴포넌트인 텍스트 입력 필드, 텍스트 영역, 날짜 입력 필드, 달력, 파일 업로드를 다룹니다. 모두 2025-01-15에 최초 등록되었습니다(Figma v1.0.0, HTML Component Kit v1.0.1).

**규칙** 표의 강도는 `SKILL_ko.md`의 표기를 따릅니다. KRDS는 컨트롤 테두리와 아이콘의 3:1 명도 대비에 KWCAG 2.2 "텍스트 콘텐츠의 명도 대비"(5.4.3)를 인용합니다. KWCAG 2.2에는 비텍스트 대비 항목이 따로 없으므로, 이 스킬은 KRDS의 인용을 유지하고 WCAG 1.4.11 Non-text Contrast를 덧붙입니다.

## 텍스트 입력 필드 (text input)

글자, 숫자, 기호로 이루어진 한 줄의 짧은 텍스트를 입력하는 데 사용합니다.

- **적합한 경우**: 한 줄로 예상되는 값(이름, 전화번호, 생년월일, 최솟값과 최댓값이 정해진 숫자). 예측할 수 없는 임의의 답변은 라디오 버튼이나 셀렉트 대신 텍스트 입력 필드로 받습니다
- **부적합한 경우**: 여러 줄 텍스트(텍스트 영역 사용). 내용이나 형식이 정해진 값(라디오 버튼, 체크박스, 셀렉트 사용)
- **구조**: 1 레이블, 2 입력 필드(배경과 구분됨), 3 도움말(선택, 도움말 또는 오류 메시지), 4 플레이스홀더(선택, 힌트 또는 예시)

**규칙**

| 규칙 | 강도 | KWCAG | 검사 방법 |
|------|------|-------|-----------|
| 필드 크기는 예상되는 텍스트에 맞춥니다. 기본은 섹션 전체 너비이고, 길이를 예측할 수 있는 값(이름, 우편번호, 전화번호)은 최대 길이에 맞춰 고정합니다. 작은 화면에서 값이 잘리지 않는지 점검합니다 | `R` | — | |
| 모든 텍스트 입력 필드에 레이블을 제공합니다. 명확한 이유가 있을 때만 생략합니다 | `G` | — | |
| 플레이스홀더를 레이블이나 도움말의 대체 수단으로 사용해서는 안 됩니다. 입력하기 시작하면 사라지고, 브라우저가 최소 명도 대비보다 낮게 표시합니다 | `R` | — | 형식이나 안내가 `placeholder`에만 있지 않은지 확인합니다 |
| 복사와 붙여넣기를 제한하지 않습니다 | `G` | — | |
| 사용자가 자주 입력하는 값(개인정보)에 자동 완성을 사용하게 합니다 | `G` | — | `autocomplete`를 지정했는지 확인합니다 |
| 모든 입력 필드의 초점을 시각적으로 확인할 수 있게 하며, 직접 만든 필드는 특히 유의합니다 | `R` | 6.1.2 초점 이동과 표시 | Tab으로 각 필드에 이동하여 초점이 보이는지 확인합니다 |
| 필드의 테두리나 배경색은 인접 배경과 3:1 명도 대비를 갖게 합니다 | `G` | 5.4.3 (WCAG 1.4.11) | |
| `<label>`, `title`, `aria-label`, `aria-labelledby` 중 하나로 필드에 접근 가능한 이름을 제공합니다. 레이블을 눌러도 필드에 초점이 가도록 `<label>`을 우선 사용합니다 | `R` | 7.3.2 레이블 제공 | |

**키보드**: 레이블이나 필드를 Click하면 커서가 놓입니다. Tab과 Shift + Tab으로 사용 불가 상태를 제외한 모든 필드에 접근합니다.

**마크업**

| 구성 요소 | 필수 | 선택 |
|-----------|------|------|
| 입력 | `.krds-input` | `.form-conts`의 상태 `.is-error`, `.is-success`(코드에는 `.is-information`도 나옵니다). 크기 `.small`, `.medium`, `.large` |

- 읽기 전용과 사용 불가는 `readonly`와 `disabled` 속성으로 나타냅니다.
- `<label>`을 연결할 수 없다면 `title`을 제공합니다(KRDS 개발 시 유의 사항).
- 필드 안의 아이콘 버튼(비밀번호 표시, 삭제)은 `.form-conts.btn-ico-wrap` 안에 `button.krds-btn.medium.icon`과 `sr-only` 이름으로 둡니다.

```html
<div class="form-group">
  <div class="form-tit"><label for="pw">비밀번호</label></div>
  <div class="form-conts btn-ico-wrap">
    <input type="password" id="pw" class="krds-input" autocomplete="new-password" aria-describedby="pw_hint">
    <button type="button" class="krds-btn medium icon" aria-pressed="false">
      <span class="sr-only">비밀번호 표시</span><i class="svg-icon ico-pw-visible" aria-hidden="true"></i>
    </button>
  </div>
  <p class="form-hint" id="pw_hint">영문자, 숫자, 특수문자를 조합해 8~12자로 입력하세요.</p>
</div>
```

- `D`: KRDS의 비밀번호 예시는 조합 규칙을 도움말 없이 플레이스홀더로만 제공하므로 KRDS 자신의 플레이스홀더 규칙을 어깁니다. 바로잡은 예시는 이를 연결된 도움말로 옮깁니다.
- `D`: 비밀번호 표시 버튼은 이름을 바꾸거나("표시"/"숨기기"), 이름은 하나로 두고 `aria-pressed`를 전환하는 방식 중 하나만 사용합니다. 두 가지를 함께 쓰지 않습니다.

## 텍스트 영역 (textarea)

여러 줄의 텍스트를 입력하는 데 사용합니다.

- **적합한 경우**: 여러 줄로 예상되는 입력
- **부적합한 경우**: 여러 질문에 대한 답변을 한꺼번에 받는 경우. 질문을 나누고 가능하면 라디오 버튼이나 체크박스를 사용합니다
- **구조**: 1 레이블, 2 입력 영역, 3 플레이스홀더(선택), 4 글자 수(입력 가능한 글자 수와 입력한 글자 수)

**규칙**

| 규칙 | 강도 | KWCAG | 검사 방법 |
|------|------|-------|-----------|
| 높이는 예상되는 최대 텍스트 길이에 비례하게 하여, 스크롤하지 않고도 적절한 분량이 보이게 합니다 | `G` | — | |
| 모든 텍스트 영역에 레이블을 제공합니다 | `G` | — | |
| 플레이스홀더를 레이블이나 도움말의 대체 수단으로 사용해서는 안 됩니다 | `R` | — | |
| 복사와 붙여넣기를 제한하지 않습니다 | `G` | — | |
| 글자 수를 제한한다면 최대 글자 수와 남은 글자 수를 레이블 다음이나 입력 영역 다음에 표시하고, 입력에 따라 갱신합니다 | `R` | — | 입력하면 글자 수가 바뀌는지 확인합니다 |
| 입력 영역은 인접 배경과 3:1 명도 대비를 갖게 합니다 | `G` | 5.4.3 (WCAG 1.4.11) | |
| 텍스트 영역에 접근 가능한 이름(`<label>`, `title`, `aria-label`, `aria-labelledby`)을 제공합니다 | `R` | 7.3.2 레이블 제공 | |

**키보드**: Tab과 Shift + Tab으로 필드에 접근합니다. 기본 높이를 넘는 내용은 방향키와 마우스 휠로 스크롤합니다.

**마크업**: `.textarea-wrap`(전체 영역)과 `.krds-input`(텍스트 영역)이 필수이며, 글자 수는 `span.count-now`와 `span.count-total`이 들어 있는 `p.textarea-count`입니다.

```html
<div class="form-group">
  <div class="form-tit"><label for="memo">문의 내용</label></div>
  <div class="form-conts"><div class="textarea-wrap">
    <textarea id="memo" class="krds-input" maxlength="100" aria-describedby="memo_count"></textarea>
    <p class="textarea-count" id="memo_count" aria-live="polite">
      <span class="count-now">0</span><span class="count-total">/100</span>
    </p>
  </div></div>
</div>
```

- `D`: KRDS의 예시는 글자 수가 고정되어 있고, `maxlength`가 없으며, 글자 수와 필드가 연결되어 있지 않습니다. 스크립트로 글자 수를 갱신하고, `aria-describedby`로 연결하며, `aria-live="polite"`를 사용합니다(입력할 때마다 읽히지 않도록 한도에 가까워졌을 때만 알려도 됩니다).

## 날짜 입력 필드 (date input)

날짜나 기간을 입력하거나 선택하는 데 사용합니다.

- **구조**: 1 레이블, 2 입력 필드, 3 달력 아이콘 버튼(선택, 달력을 표시하거나 숨김), 4 도움말(선택), 5 플레이스홀더(선택, 날짜 형식 힌트)

**유형**

| 유형 | 사용하는 경우 | 예시 |
|------|---------------|------|
| 다중 입력 필드(년, 월, 일) | 문서와 날짜가 정확히 일치해야 할 때 사용합니다. 필드 사이를 이동해야 하므로 효율성이 가장 낮은 입력 방식입니다. 년이나 일은 생략할 수 있습니다 | 카드 유효기간, 여권 발급 일자, 생년월일 |
| 단일 입력 필드 | 사용자가 날짜를 알고 있을 때 사용합니다. 더 유연합니다. 사용자가 날짜를 기억하지 못할 수 있다면 날짜 선택기를 **함께 제공해야** 합니다 | 주민등록번호 앞자리, 생년월일 |
| 범위 입력 필드(단일 입력 필드 두 개) | 시작일과 종료일에 사용하며, 대략적인 날짜에도 사용합니다. 사용자가 범위를 기억하지 못할 수 있다면 날짜 선택기를 **함께 제공해야** 합니다 | 검색과 목록 화면의 날짜 필터 |
| 날짜 선택기가 있는 입력 필드 | 오늘에서 먼 날짜, 요일이 중요한 경우, 인접한 날짜를 비교해야 하는 경우에 사용합니다 | 예약일, 방문일 |

- **부적합한 경우**: 상대 날짜("5일 이내", "1일 후")는 짧은 텍스트 입력이나 허용되는 옵션을 담은 셀렉트를 사용합니다

**규칙**

| 규칙 | 강도 | KWCAG | 검사 방법 |
|------|------|-------|-----------|
| 모든 날짜 필드에 레이블을 제공하고 어떤 날짜를 입력해야 하는지 설명합니다. 필드가 여러 개이면 년, 월, 일에 각각 레이블을 붙이고 상단에 설명을 둡니다 | `R` | — | |
| 필드 아래의 도움말에 날짜 형식을 안내합니다. 플레이스홀더에 `YYYY-MM-DD`를 보여 줄 수 있지만, 자릿수와 작성 예시는 도움말에 적습니다 | `R` | — | 입력을 시작한 뒤에도 형식이 보이는지 확인합니다 |
| 문서에 인쇄된 날짜를 요청할 때는 필드 구성을 원본 문서와 일치시키고, 붙여넣기 쉽게 합니다 | `G` | — | |
| 정확한 날짜를 기억하기 어렵다면 대략적인 날짜(월만, 또는 범위)를 입력할 수 있게 합니다 | `R` | — | |
| 사용자가 자주 입력하는 날짜(생년월일)에 자동 완성을 사용하게 합니다 | `G` | — | `autocomplete="bday"` |
| 날짜 선택기가 있더라도 키보드로 날짜를 직접 입력할 수 있게 하고, 필드를 사용 불가나 읽기 전용으로 만들지 않습니다 | `R` | 6.1.1 키보드 사용 보장 | 날짜 선택기 없이 날짜를 입력할 수 있는지 확인합니다 |
| 일, 월, 연도 필드의 레이블을 정확하게 지정하고 프로그램적으로 연결합니다 | `R` | 7.3.2 레이블 제공 | |
| 형식이 정해져 있다면 도움말에 안내합니다 | `R` | — (WCAG 3.3.2) | |

**키보드**: 레이블이나 필드를 Click하면 커서가 놓이고, Tab과 Shift + Tab으로 모든 필드에 접근합니다. 달력은 별도 표(아래)를 따릅니다.

**마크업**: `.form-group`, `.form-tit`, `.calendar-input`(입력 영역), `.form-btn-datepicker`(달력 버튼), `.form-hint`가 필수입니다. 키트의 스크립트는 입력 필드에 `datepicker cal` 클래스가 있을 때만 선택한 날짜를 필드에 채웁니다. 스크립트 `krds_calendar`는 `init()`, `openDatePicker()`, `closeAllDatePickers()`, `toggleDateSelector()`를 제공합니다.

```html
<div class="form-group">
  <div class="form-tit"><label for="visit">방문 희망일</label></div>
  <div class="form-conts calendar-conts">
    <div class="calendar-input">
      <input type="text" id="visit" class="krds-input datepicker cal" inputmode="numeric"
             placeholder="YYYY.MM.DD" aria-describedby="visit_hint">
      <button type="button" class="krds-btn medium icon form-btn-datepicker" aria-expanded="false">
        <span class="sr-only">달력 열기</span><i class="svg-icon ico-calendar"></i>
      </button>
    </div>
    <div class="krds-calendar-area"><!-- calendar --></div>
  </div>
  <p class="form-hint" id="visit_hint">숫자 8자리로 입력하세요. 예: 2026.11.06</p>
</div>
```

- `D`: KRDS의 코드는 `YYYY.MM.DD` 플레이스홀더에 `type="number"`를 사용하는데, 숫자 필드는 그 텍스트를 담을 수 없습니다(데모 스크립트가 type을 바꿉니다). `inputmode="numeric"`을 지정한 `type="text"`를 사용합니다.
- `D`: 규칙은 `YYYY-MM-DD`를, 코드는 `YYYY.MM.DD`를 보여 줍니다. KRDS는 둘 중 어느 것도 확정하지 않으므로, 사이트 전체에서 구분자를 하나로 정하고 도움말에 명시합니다.

## 달력 (calendar)

날짜와 관련된 정보와 기능을 보여 주며, 날짜 입력 필드의 날짜 선택기로도 사용합니다.

- **적합한 경우**: 정기적으로 제공되는 날짜별 서비스. 여러 날짜를 비교해야 하는 경우. 오늘과 가까운 날짜를 확인하거나 선택하는 경우
- **부적합한 경우**: 정기적으로 갱신되지 않는 정보이거나 한 달에 이벤트가 2개 이하인 경우(KRDS는 대안을 밝히지 않으며, `D`: 목록을 사용합니다)
- **구조**: 1 연/월(선택할 수 있게 할 수 있음), 2 이전/다음 버튼, 3 그리드, 4 요일 제목, 5 날짜(버튼), 6 오늘(식별자 포함), 7 선택한 날짜(식별자 포함), 8 선택할 수 없는 날짜(선택), 9 이전 달과 다음 달의 날짜, 10 이벤트(선택)

**규칙**

| 규칙 | 강도 | KWCAG | 검사 방법 |
|------|------|-------|-----------|
| 날짜의 상태(오늘, 선택됨, 활성화되지 않음, 선택할 수 없음)와 범례(휴관일, 공휴일)는 달력이 나타나는 모든 곳에서 일관되게 표현합니다 | `R` | — | |
| 상태를 텍스트나 배경색만으로 구분하지 않고, 텍스트 굵기, 밑줄, 형태, 추가 식별자로 구분합니다. 오늘과 선택한 날짜에는 텍스트를 붙일 수 있습니다 | `R` | — | |
| 이벤트가 복잡하다면 별도의 목록이나 표를 제공하거나, 주 또는 일 단위 보기로 전환합니다 | `R` | — | |
| 그리드에 요일 제목을 항상 제공합니다 | `R` | — | 요일마다 `th`가 있는지 확인합니다 |
| 날짜의 의미를 색상으로만 전달하지 않습니다(밑줄, 1px 이상의 테두리 차이, 식별자 사용) | `R` | 5.4.1 색에 무관한 콘텐츠 인식 | |

**키보드**

| 키 | KRDS 동작 |
|----|-----------|
| Tab, Shift + Tab | 달력의 컨트롤을 순서대로 이동합니다 |
| Click, Enter | 액션 버튼을 실행하거나 링크로 이동합니다 |

- `D`: KRDS는 Tab과 Enter만 정의합니다. 28개에서 31개의 버튼으로 이루어진 그리드에서는 이동이 느립니다. WAI-ARIA의 날짜 선택기 대화상자 패턴에 따라 그리드를 Tab 정지점 하나로 만들고, 방향키로 이동하며, Home/End(주), PageUp/PageDown(월), Esc(닫고 달력 버튼으로 초점 복귀)를 지원합니다.

**마크업**

| 구성 요소 | 필수 | 선택 |
|-----------|------|------|
| 전체 영역 | `.calendar-conts` | |
| 달력 | `.krds-calendar-area` | 단일 날짜 선택 `.calendar-wrap.single` |
| 헤더(연, 월, 이동) | `.calendar-head` | |
| 그리드 | `.calendar-body` | 선택됨 `td.period.start.end`, 선택할 수 없음 `td.old`, `td.new`, `td.disabled`, 이벤트 `td.day-event`, 오늘 `td.today`, 공휴일 `td.day-off` |
| 푸터 | `.calendar-footer` | |

- 그리드는 `caption`과 요일 `th`가 있는 `table.calendar-tbl`이며, 각 날짜는 `td > button.btn-set-date`입니다. 푸터에는 오늘, 취소, 확인이 있습니다. KRDS의 스크립트는 `aria-label` "N 오늘"과 "N 일정있음", 선택한 날짜의 `aria-pressed`, 열린 버튼의 `aria-expanded`, 열려 있는 동안의 초점 가두기를 추가하며, 닫을 때는 열기 버튼으로 초점을 되돌립니다.
- `D`: KRDS의 구조는 이전 달과 다음 달의 날짜를 "선택할 수 있음"이라 하지만, 선택자 표는 `td.old`/`td.new`를 선택할 수 없는 날짜에 분류하고 데모는 이를 비활성화합니다. 서비스마다 정하고, 상태가 눈에 보이고 읽히도록 합니다.
- `D`: KRDS의 스크립트는 공휴일(`td.day-off`)에 텍스트를 부여하지 않아 KRDS 자신의 범례 규칙을 어깁니다. 텍스트를 추가합니다(예: `aria-label="25일 공휴일"`).

## 파일 업로드 (file upload)

로컬 파일을 하나 이상 선택하고 첨부하는 데 사용합니다.

- **구조**: 1 레이블 또는 제목(업로드의 목적), 2 설명(선택), 3 도움말(과정, 요구 사항, 형식, 크기), 4 파일 선택 버튼, 5 드롭 영역, 6 카운터(업로드할 수 있는 수와 업로드한 수), 7 파일 항목(이름, 확장자, 크기), 8 삭제 버튼, 9 상태 아이콘(업로드 중에는 스피너, 성공하면 성공 아이콘이며 이후 삭제 버튼으로 바뀜)

**유형**: 단일 파일 업로드(파일 하나, 또는 서로 관련 없는 파일을 섹션을 나누어 컴포넌트 하나씩 사용)와 다중 파일 업로드(앨범처럼 서로 관련된 파일). 방식별로는 파일 선택 버튼, 드래그 앤 드롭이 있습니다.

- **부적합한 경우**: 모달에서의 다중 업로드(파일 목록이 세로로 길어집니다)

**규칙**

| 규칙 | 강도 | KWCAG | 검사 방법 |
|------|------|-------|-----------|
| 파일 업로드는 필요한 경우에만 사용하고, 불필요한 파일을 요청하지 않습니다 | `R` | — | |

| 파일 형식, 크기, 개수의 제한을 도움말에 안내합니다 | `G` | — | |
| 형식은 가능한 한 제한하지 않으며, 한 형식의 모든 확장자(`.jpg`, `.jpeg`, `.jpe`)를 허용합니다 | `R` | — | |
| 크기는 가능한 한 제한하지 않으며, 제한이 필요하다면 일반적인 파일이 들어가도록 정합니다 | `R` | — | |
| 크기 제한이 있는 이미지 파일에는 자동 압축을 고려합니다 | `G` | — | |
| 업로드한 뒤에도 파일 선택 버튼(또는 드롭 영역)을 활성화된 상태로 유지하여 파일을 추가하거나 바꿀 수 있게 합니다. 사용 불가 상태는 입력 자체를 막을 때만 사용합니다 | `G` | — | |
| 파일 선택 버튼의 강조 수준을 제출 버튼보다 낮게 합니다 | `G` | — | 기본 제출 버튼 옆에서 `.primary`를 쓰지 않았는지 확인합니다 |
| 사용자가 폼을 제출하기 전에는 파일을 업로드하거나 저장하지 않습니다 | `R` | — | 파일을 선택할 때 요청이 전송되지 않는지 확인합니다 |
| 각 경우(파일 없음, 잘못된 형식, 너무 큼, 비어 있음, 업로드 실패, 개수 초과)마다 구체적인 오류를 제공하며, 비밀번호로 보호된 파일이나 바이러스는 감지할 수 있다면 추가합니다 | `G` | — | |

| 업로드의 목적을 설명하는 적절한 레이블을 제공합니다 | `R` | 7.3.2 레이블 제공 | |

| 삭제 | 삭제 버튼에서 Click, Space, Enter를 누릅니다 |

**마크업**: `.krds-file-upload`(전체 영역), `.file-upload`(업로드 영역), `.file-list`(업로드한 파일)가 필수입니다. 항목은 `.file-name`과 `.btn-wrap`이 있는 `ul.upload-list > li > .file-info`이며, 오류는 `p.file-hint-invalid`가 있는 `li.is-error`입니다.

  </div>

- `D`: KRDS의 예시는 파일 입력에 `hidden` 속성을 사용하고(접근성 트리에서 제외되므로 KRDS 자신의 규칙을 어깁니다), 삭제 버튼에 `aria-describedby`가 없으며, `<label>` 안에 `<button>`을 중첩합니다. 바로잡은 예시는 시각적으로만 숨긴 입력과 버튼처럼 꾸민 레이블을 사용합니다. 이 경우 키보드 초점은 숨겨진 입력에 놓이므로 `#up_file:focus-visible + label`로 레이블에 초점 링을 그려야 하며, 그렇지 않으면 "초점이 보여야 한다"는 규칙을 어깁니다.
- 위의 클라이언트 측 검사는 사용성 규칙입니다. 확장자, 크기, 저장 위치를 서버 측에서 검사하는 일은 별도로 필요합니다. `secure-coding`의 보안약점 6번(위험한 형식 파일 업로드)을 참조합니다.
