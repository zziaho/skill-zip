# 신청 및 로그인 서비스 패턴

폼에 쓰는 KRDS 서비스 패턴인 신청 개요와 체크리스트, 신청서 작성, 확인/확정, 로그인 정보 입력을 다룹니다. 모두 2025-01-15에 최초 등록되었습니다(Figma v1.0.0, HTML Component Kit v1.0.1).

서비스 패턴의 규칙에는 KRDS의 적용 수준이 붙어 있습니다. 이 스킬은 **필수는 `R`**, **권장과 우수는 `G`**로 대응시킵니다(`SKILL_ko.md`). KRDS는 이렇게 설명합니다. "서비스 패턴의 사용성 가이드라인은 사용자 관점의 중요도와 만족도에 따라 세 단계로 나뉘며, 핵심 서비스는 최소한 가장 낮은 단계인 필수를 충족해야 한다." KRDS는 권장과 우수를 더 자세히 정의하지 않습니다.

## 신청 개요 (application overview)

신청은 사용자가 폼을 작성하여 기관에 필요한 것을 알리는 과업입니다. 법령에서 정한 민원뿐 아니라 사용자의 모든 요청을 포함합니다.

| 유형 | 의미 | 예시 |
|------|------|------|
| 제출 | 정해진 양식을 작성하여 제출합니다 | 복지 급여, 전입신고, 반환 신고 |
| 조회 | 자격, 문서의 유효성, 결과를 확인합니다 | 문서 진위 확인, 세액 |
| 발급 | 증명서나 번호를 발급합니다 | 주민등록등본, 통관 고유번호, 자동차 등록 |
| 예약 | 일정 기간 물품이나 서비스의 이용을 신청합니다 | 도서, 좌석, 입장권 |

**흐름**: 1 서비스 찾기(목록 탐색, 하나 이상 선택, 신청), 2 신청서 작성(단계 이동, 데이터 입력, 인증이나 이전 입력으로 자동 채움, 도움말, 양식 안내서, 문서 첨부, 여러 건 신청, 임시 저장), 3 확인과 제출(최종 확인, 제출 확정, 취소), 4 결과 확인(결과 화면 찾기, 날짜나 상태별 탐색, 진행 상황 확인). 체크리스트에는 흐름에 없는 세 단계인 서비스 정보, 유의 사항과 신청 자격, 완료가 추가되어 있습니다.

신청 흐름의 2단계입니다.

## 확인/확정 (confirm and submit)

신청 흐름의 3단계이며, 완료 전의 마지막 단계입니다.

**구조**: 1 제목(요청한 행동의 요약), 2 설명(선택), 3 확인할 정보, 4 액션(제출, 또는 중단하고 폼으로 돌아감).

**유형**: 모달(핵심 정보가 적어 스크롤이 필요 없음) 또는 단일 화면(구조화가 필요한 정보가 많음). 여러 단계의 신청에서 단일 화면으로 구성할 때는 단계 표시기를 권장합니다.

**규칙**

| 규칙 | 적용 수준 | 강도 | 검사 방법 |
|------|-----------|------|-----------|
| 제출 후에 취소, 철회, 수정할 수 없는 신청에는 확인 단계를 포함합니다. 반복해서 처리할 수 있는 발급 유형의 서비스는 생략할 수 있습니다 | 필수 | `R` | |
| 핵심 정보만 요약합니다. 회신을 받을 연락처, 변경할 수 없는 항목(예: 여권 신청의 로마자 이름), 심사에 영향을 주는 항목(예: 소득)이 해당합니다 | 권장 | `G` | |
| 신청을 취소하거나 수정할 수 없다는 점을 제목, 표제, 설명에 명시합니다 | 필수 | `R` | 문구가 암시에 그치지 않고 실제로 있는지 확인합니다 |
| 확정 버튼과, 폼으로 돌아가는 취소 버튼을 모두 제공합니다 | 필수 | `R` | |

- KRDS는 이 페이지에 접근성 규칙을 제시하지 않습니다. 모달 유형에는 `form-patterns_ko.md`(확인)의 대화상자 규칙을 적용합니다.

**비밀번호 자동 완성과 secure-coding** (`D`)

KRDS는 로그인 필드에 `autocomplete`를 지정하라고 요구하고 붙여넣기를 막는 것을 금지합니다. 행정안전부의 2021년 개발보안 가이드(`secure-coding`, 설계 기준 SR2-7)는 인증 정보를 받는 폼에 `autocomplete="off"`를 요구합니다. 이 스킬은 KRDS를 따릅니다.

- KWCAG 2.2 7.3.3 접근 가능한 인증은 인증이 기억이나 옮겨 적기에 의존하지 않을 것을 요구하며, 이를 충족하는 일반적인 방법이 비밀번호 관리자와 붙여넣기입니다.
- 최근의 브라우저는 대부분 로그인 필드의 `autocomplete="off"`를 어차피 무시하므로, SR2-7이 의도한 효과를 거두지 못합니다.
- `autocomplete="username"`, `"current-password"`(로그인), `"new-password"`(회원가입, 변경)를 사용합니다. 진단원이 SR2-7을 근거로 지적하면 KWCAG 7.3.3과 KRDS로 이 선택을 설명하고, 프로젝트의 보안 설계에 기록합니다.

**KRDS가 다루지 않는 보안 규칙** (`D`)

| 주제 | 적용 방법 |
|------|-----------|
| 오류 메시지의 내용 | 아이디나 비밀번호가 올바르지 않다고만 알리고 어느 쪽인지는 밝히지 않아, 아이디를 알아내는 열거를 막습니다. 복구 방법(아이디 찾기, 비밀번호 재설정)을 함께 알린다면 KRDS의 "명확하고 구체적으로" 규칙도 여전히 충족합니다 |
| 시도 횟수 제한, 계정 잠금, CAPTCHA | `secure-coding` 보안약점 33번과 설계 기준 SR2-2 |
| 비밀번호 규칙 | `secure-coding` 보안약점 26번과 설계 기준 SR2-3 |
| "로그인 정보 저장" 쿠키 | 유효 기간을 짧게 유지하고 쿠키에 인증 정보를 저장하지 않습니다. `secure-coding` 보안약점 29번 |
