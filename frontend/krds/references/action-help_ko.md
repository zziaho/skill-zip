# 액션, 피드백, 도움 (버튼, 단계 표시기, 맥락적 도움말, 툴팁)

폼 주변에서 쓰는 KRDS 컴포넌트입니다. 모두 2025-01-15에 최초 등록되었으며(Figma v1.0.0, HTML Component Kit v1.0.1), 맥락적 도움말은 2025-03-05에 변경되었습니다(HTML Component Kit v1.0.4: 사용자가 레이어 바깥을 눌러야만 레이어가 닫힙니다).

**규칙** 표의 강도는 `SKILL_ko.md`의 표기를 따릅니다.

## 버튼 (button)

기능을 실행하거나 상태를 변경합니다. 스타일은 액션의 중요도를 반영합니다.

- **구조**: 1 텍스트 레이블(모든 버튼에 있으며, 아이콘만 있는 버튼은 시각적으로 숨김), 2 컨테이너(선택), 3 아이콘(선택)
- **적합한 경우**: 폼 제출, 대화상자 실행, 취소, 일반 기능, 상태 변경, 도움말, 진행 중인 과정 중지, 영구 삭제
- **부적합한 경우**: 완전히 다른 화면이나 서비스로 이동하거나 새 창이나 새 탭을 여는 경우. 링크를 사용합니다

**규칙**

| 규칙 | 강도 | KWCAG | 검사 방법 |
|------|------|-------|-----------|
| 그룹 안의 모든 버튼은 크기를 같게 하고, 위계는 크기가 아니라 스타일로 나타냅니다 | `G` | — | |
| 위계는 과업의 중요도를 따릅니다. 주 색상으로 채운 버튼은 강조(핵심 액션), 윤곽선 버튼은 기본(중간), 텍스트 버튼은 가장 낮은 수준(다수의 기능)입니다 | `G` | — | |
| 최상위 강조 버튼은 페이지에서 한 번만 사용합니다 | `G` | — | 가장 강조된 버튼이 페이지에 하나뿐인지 확인합니다 |
| 세로 버튼 그룹(패널, 모바일)에서는 최상위 버튼을 가장 먼저 둡니다 | `R` | — | |
| 버튼 레이블은 결과를 예측할 수 있는 동사로 작성합니다. 일반적인 액션(완료, 닫기, 취소, 추가, 삭제)이거나 동사를 쓰면 레이블이 너무 길어지거나 불분명해지는 경우는 예외입니다 | `R` | — | 신청서를 제출하는 버튼은 "확인"이 아니라 "신청하기"입니다 |
| 아이콘은 중요한 액션에 필요한 경우에만 사용하며, 아이콘의 의미는 텍스트 레이블과 밀접하게 관련되어야 **합니다**. 널리 알려진 것(설정, 닫기, 좋아요)을 제외하고는 아이콘만 있는 버튼을 피합니다. 아이콘이 있는 버튼은 없는 버튼보다 더 강조되어야 합니다. 가장 중요한 액션에 아이콘이 없다면 낮은 수준의 액션에도 아이콘을 **쓰지 않아야** 합니다 | `R` | — | |
| 두 번 누르는 경우(느린 네트워크, 손떨림)를 예상하여, 데이터를 전송하는 버튼은 두 번째 상호작용을 무시**해야** 합니다 | `R` | — | 더블 클릭해도 요청이 한 번만 전송되는지 확인합니다 |
| 모든 버튼에 기능을 설명하는 접근 가능한 이름을 제공합니다 | `R` | 6.4.3 적절한 링크 텍스트 (KRDS의 인용, WCAG 4.1.2) | |
| 텍스트 레이블이 이미 있는 버튼의 아이콘에는 대체 텍스트를 제공하지 않습니다 | `R` | 5.1.1 적절한 대체 텍스트 제공 | 장식 아이콘에 `aria-hidden`을 쓰거나 대체 텍스트를 비워 두었는지 확인합니다 |
| 아이콘만 있는 버튼의 이름은 이미지가 아니라 기능을 설명합니다 | `R` | 6.4.3 적절한 링크 텍스트 (WCAG 2.4.6) | "돋보기"가 아니라 "검색" |
| 사용 불가 상태를 제외한 모든 버튼에 키보드로 접근하고 조작할 수 있게 합니다 | `R` | 6.1.1 키보드 사용 보장 | |
| 초점이 보이게 합니다. 가능하면 사용자 에이전트의 포커스링을 유지하고, 스타일을 바꾸더라도 숨겨서는 안 되며 3:1 명도 대비가 필요합니다 | `R` | 6.1.2 초점 이동과 표시 | |
| 버튼으로 동작하는 것은 모두 버튼으로 읽혀야 합니다. `<button>`을 사용하고, 다른 요소를 쓸 수밖에 없다면 `role="button"`을 사용합니다 | `R` | — (WCAG 4.1.2) | 역할이 없는 클릭 가능한 `div`가 없는지 확인합니다 |
| 대상 크기는 마우스에서 최소 17 × 17px, 터치에서 최소 44 × 44px로 합니다 | `G` | 6.1.3 조작 가능 | |

**키보드**: Tab과 Shift + Tab으로 모든 버튼에 접근하고, Click, Enter, Space로 실행합니다.

**마크업**

| 구성 요소 | 필수 | 선택 |
|-----------|------|------|
| 버튼 | `.krds-btn` | 색상 `.primary`, `.secondary`, `.tertiary`. 크기 `.xsmall`, `.small`, `.medium`, `.large`, `.xlarge`. 텍스트 스타일 `.text`. 아이콘만 있는 버튼 `.icon`, 테두리와 배경이 있으면 `.icon.border` |

- KRDS는 채움, 윤곽선, 텍스트 강조가 각각 어느 클래스에 해당하는지 밝히지 않습니다. `D`: 최상위 버튼 하나에 `.primary`를 대응시키기 전에 Figma 라이브러리에서 확인합니다.
- KRDS는 제출 버튼과 취소 버튼의 순서에 관한 규칙을 제시하지 않습니다. 입력 폼 패턴(`form-patterns_ko.md`: 제출 버튼은 오른쪽 끝)을 따릅니다.

```html
<div class="btn-wrap">
  <button type="button" class="krds-btn medium tertiary">임시 저장</button>
  <button type="button" class="krds-btn medium secondary">이전</button>
  <button type="submit" class="krds-btn medium primary">신청하기</button>
</div>
<button type="button" class="krds-btn medium icon"><span class="sr-only">검색</span><i class="svg-icon ico-sch" aria-hidden="true"></i></button>
```

- `D`: 버튼에는 항상 `type`을 지정합니다. KRDS의 도움말 아이콘 버튼에는 `type`이 없어서 폼 안에서 누르면 폼이 제출됩니다.

## 단계 표시기 (step indicator)

서비스의 단계와 현재 진행 상황을 보여 줍니다.

- **구조**: 1 단계 번호(작은 화면에서는 "4단계 중 1단계"만 보여 줄 수 있음), 2 단계 레이블, 3 현재 단계 식별자, 4 완료한 단계 식별자, 5 연결선

**규칙**

| 규칙 | 강도 | KWCAG | 검사 방법 |
|------|------|-------|-----------|
| 단계 레이블은 짧고 명확하게 작성합니다. 추가 텍스트는 레이블 옆에 둘 수 있지만, 레이블 자체가 잘리거나 줄 바꿈되어서는 **안 됩니다** | `R` | — | |
| 단계는 논리적으로 왼쪽에서 오른쪽 또는 위에서 아래로, 연결선이나 화살표, 쉐브론과 함께 배치하며, 사이트 전체에서 일관되게 합니다 | `R` | — | |
| 단계는 3개에서 7개로 구성합니다. 불필요한 단계는 없애고, 문제가 없는 과업은 한 단계로 끝냅니다 | `G` | — | |
| 현재 단계를 다른 단계와 명확하게 구분합니다 | `R` | — | |
| 이동 방식을 선택합니다. 순차형(현재 단계를 끝내기 전까지 다음 단계가 비활성화됨) 또는 적응형(단계를 건너뛰거나 어떤 순서로든 방문할 수 있음) | `G` | — | |
| 선택 단계는 필수 단계 뒤에 두고 명확한 레이블(건너뛰기, 다음에 입력하기)로 건너뛸 수 있게 합니다. 남은 필수 단계가 없다면 마지막 검토로 건너뜁니다 | `R` | — | |
| 순서가 있는 목록(`ol`, `li`)을 사용합니다 | `R` | 6.4.2 제목 제공 (KRDS의 인용, WCAG 1.3.1) | |
| 현재 단계와 완료한 단계를 색상만으로 구분하지 않습니다 | `R` | 5.4.1 색에 무관한 콘텐츠 인식 | |
| 스크린 리더가 현재 단계를 식별할 수 있게 합니다. 레이블에 "현재" 텍스트가 없으면 `aria-current`를 추가하고, `aria-current`를 쓸 수 없으면 "현재 단계"를 보이는 텍스트나 `sr-only` 텍스트로 추가합니다 | `R` | 5.1.1 적절한 대체 텍스트 제공 (KRDS의 인용, WCAG 4.1.2) | |

**마크업**

| 구성 요소 | 필수 | 선택 |
|-----------|------|------|
| 전체 영역 | `.krds-step-wrap`(`ol`에 지정) | |
| 단계 | `> li` | 완료 `.done`, 현재 `.active` |
| 레이블 | `.step-tit` | |

```html
<ol class="krds-step-wrap">
  <li class="done"><span><i class="step">1단계</i><span class="step-tit">신청인 정보<span class="sr-only">(완료)</span></span></span></li>
  <li class="active" aria-current="step"><span><i class="step">2단계</i><span class="step-tit">신청 내용</span></span></li>
  <li><span><i class="step">3단계</i><span class="step-tit">확인</span></span></li>
</ol>
```

- `D`: KRDS는 `aria-current="true"`를 쓰지만, ARIA 값 `step`이 이 경우를 위한 값이며 "현재 단계"로 읽힙니다. KRDS의 예시는 대신 `sr-only` "현재단계" 텍스트를 쓰며, 이는 KRDS의 규칙도 허용하는 방식입니다. KRDS는 완료한 단계에 텍스트를 붙이지 않습니다. `D`: 상태가 시각적으로만 전달되지 않도록 "(완료)"를 추가합니다.

## 맥락적 도움말 (contextual help)

컴포넌트 옆에 그 상태나 상세 정보를 보여 주는 팝오버이며, 사용자가 정보 또는 도움말 아이콘 버튼으로 요청할 때만 표시합니다.

- **구조**: 1 아이콘 버튼(도움말을 전환하며, 정보는 ⓘ, 도움말은 ?), 2 컨테이너, 3 제목, 4 본문(짧게 작성하며 링크 허용), 5 닫기 버튼
- **유형**: 정보(ⓘ: 컨트롤이 비활성화된 이유처럼 추가로 알아 두면 좋은 정보이며, 본문은 짧게 쓰되 해당 요소에 대한 구체적인 안내를 **담아야 합니다**), 도움말(?: 필드를 작성하는 방법처럼 이미지, 동영상, 링크가 포함된 상세한 도움말)
- **부적합한 경우**: 컨트롤의 레이블(툴팁). 과업을 완료하는 데 필요한 정보(인라인 도움말 또는 도움 패널이며, 팝오버에 숨겨서는 **안 됩니다**). 짧은 추가 정보(툴팁 또는 인라인 도움말)

**규칙**

| 규칙 | 강도 | KWCAG | 검사 방법 |
|------|------|-------|-----------|
| 아이콘 버튼은 설명하는 요소 옆에 둡니다 | `G` | — | |
| 팝오버가 화면 밖으로 나가지 않게 합니다 | `R` | — | 모든 화면 너비에서 확인합니다 |
| 팝오버가 중요한 콘텐츠(버튼이나 설명하는 요소)를 가리지 않게 합니다 | `G` | — | |
| 사용자가 반드시 알아야 하는 정보를 도움말에만 두어서는 **안 되며**, 본문에 요약해서 제공합니다 | `R` | — | |
| 맥락적 도움말에서 다른 맥락적 도움말이나 모달을 열지 않습니다 | `R` | — | |
| 도움말 안의 링크는 새 창에서 엽니다 | `G` | — | |
| 하나의 과업 흐름에서 맥락적 도움말과 도움 패널을 함께 사용하지 않습니다 | `R` | — | |
| 아이콘은 인접 배경과 3:1 명도 대비를 갖게 합니다 | `R` | 5.4.3 (WCAG 1.4.11) | |
| 각 아이콘 버튼에 이름을 제공합니다 | `R` | 6.4.3 적절한 링크 텍스트 (KRDS의 인용) | |
| 각 아이콘 버튼의 이름은 고유해야 하며 설명하는 대상을 포함합니다 | `R` | 6.4.3 적절한 링크 텍스트 (WCAG 2.4.6) | "도움말"이 아니라 "발급 방법 도움말" |
| 도움말은 사용자가 요청할 때만 열고, 페이지를 불러올 때는 열지 않습니다 | `R` | 7.2.1 사용자 요구에 따른 실행 | |
| 팝오버의 내용은 읽기 순서상 아이콘 버튼 바로 뒤에 둡니다 | `R` | 5.3.2 콘텐츠의 선형구조 (KRDS: "콘텐츠의 선형화") | |
| 초점을 논리적으로 이동합니다. 팝오버에 링크가 있다면 열릴 때 초점이 팝오버 안으로 이동하며, 키보드 트랩을 피합니다 | `R` | 6.1.2 초점 이동과 표시 | |
| 아이콘 버튼의 대상은 44 × 44 CSS px를 고려합니다. 문장 끝에 있는 버튼은 예외입니다 | `G` | 6.1.3 조작 가능 | |

**키보드**

| 키 | 동작 |
|----|------|
| 아이콘 버튼에서 Click, Enter, Space | 도움말을 표시하고, 다시 누르면 숨기며, 초점은 버튼에 유지됩니다 |
| Tab | 열려 있는 팝오버 안의 링크를 이동합니다 |
| 바깥을 Click, Esc | 도움말을 숨기고 아이콘 버튼으로 초점을 되돌립니다 |

**마크업**: `.krds-contextual-help`, `.tooltip-action`(컨트롤), `.tooltip-popover`가 필수이며, 선택은 위치 `.top.left`, `.top.center`, `.top.right`, `.bottom.left`, `.bottom.center`, `.bottom.right`입니다(스크립트가 기본으로 `top left`를 추가합니다). 스크립트 `krds_contextualHelp`는 `init()`, `setupTooltips()`, `toggleTooltip()`을 제공합니다.

```html
<div class="krds-contextual-help bottom left">
  <div class="tooltip-action">
    <button type="button" class="krds-btn medium icon tooltip-btn" aria-expanded="false" aria-controls="help_issue">
      <span class="sr-only">발급 방법 도움말</span><i class="svg-icon ico-tooltip" aria-hidden="true"></i>
    </button>
    <div class="tooltip-popover" id="help_issue">
      <h4 class="tooltip-title">발급 방법</h4>
      <div class="tooltip-contents"><p>온라인 발급은 직접 출력하거나 전자지갑으로 받을 수 있습니다.</p>
        <a href="/guide/issue" class="krds-btn xsmall link basic" target="_blank">자세히 보기<span class="sr-only">(새 창)</span></a></div>
      <button type="button" class="krds-btn xsmall icon tooltip-close"><span class="sr-only">발급 방법 도움말 닫기</span></button>
    </div>
  </div>
</div>
```

- `D`: KRDS의 스크립트는 이 팝오버에 `role="tooltip"`을 지정하지만, 툴팁에는 상호작용하는 요소를 넣을 수 없습니다(KRDS의 툴팁 페이지가 직접 밝힙니다). 디스클로저로 취급하여 버튼에 `aria-expanded`와 `aria-controls`를 사용하고 `tooltip` 역할은 사용하지 않습니다. 키트를 사용할 때는 `setupTooltips()`에서 역할을 추가하는 줄도 함께 제거해야 하며, 그렇지 않으면 마크업을 바로잡은 효과가 사라집니다.
- `D`: KRDS의 Esc와 닫기 버튼 핸들러는 팝오버를 닫지만 아이콘 버튼으로 초점을 되돌리지 않아 KRDS 자신의 키보드 표를 어깁니다. 두 경우 모두 초점을 되돌립니다.

## 툴팁 (tooltip)

요소에 대한 짧은 추가 설명이며, 포인터가 요소나 별도 트리거 버튼 위에 있거나 초점이 놓였을 때 표시합니다.

- **구조**: 1 트리거 버튼, 2 컨테이너, 3 아이콘(선택, 상태 아이콘), 4 본문
- **유형**: 정보 또는 물음표 아이콘 툴팁(컴포넌트나 레이블 옆의 추가 정보), 아이콘 버튼 툴팁(텍스트 레이블이 없는 아이콘 버튼용)
- **적합한 경우**: 아이콘만 있는 컨트롤의 레이블. 용어의 뜻처럼 꼭 필요하지는 않은 짧은 추가 정보
- **부적합한 경우**: 상호작용하는 요소가 들어 있는 콘텐츠(맥락적 도움말). 약 150자를 넘는 내용(맥락적 도움말, 도움 패널, 도움말 페이지)

**규칙**

| 규칙 | 강도 | KWCAG | 검사 방법 |
|------|------|-------|-----------|
| HTML `title` 속성보다 툴팁 컴포넌트를 우선 사용합니다(`title`은 글꼴과 위치가 고정되어 있고 스크린 리더가 읽지 않을 수 있습니다) | `G` | — | |
| 팝오버가 화면 밖으로 나가지 않게 합니다 | `R` | — | |
| 팝오버가 중요한 콘텐츠를 가리지 않게 합니다 | `G` | — | |
| 아이콘만 있는 메뉴와 기능 버튼에는 툴팁이 **있어야** 합니다 | `R` | — | |
| 툴팁은 추가 정보에만 사용하며, 필수 정보를 툴팁에만 두어서는 **안 됩니다** | `R` | — | |
| 같은 요소에 툴팁과 `title` 속성을 함께 사용하지 않습니다 | `R` | — | 스크린 리더가 두 번 읽을 수 있습니다 |
| 한 화면에서 아이콘 툴팁을 맥락적 도움말이나 도움 패널과 섞어 쓰지 않습니다(트리거는 비슷해 보이지만 동작이 다릅니다) | `R` | — | |
| 터치스크린에서는 툴팁이 hover로 나타나지 않으므로 의미가 분명한 아이콘을 고릅니다 | `R` | — | |
| 별도의 트리거 버튼이 있다면 터치 인터페이스를 감지했을 때 버튼을 누르면 팝오버가 전환되게 합니다 | `G` | — | |
| 각 트리거 버튼에 이름을 제공합니다 | `R` | 6.4.3 적절한 링크 텍스트 (KRDS의 인용) | |
| 각 트리거 버튼의 이름은 고유해야 하며 설명하는 대상을 포함합니다 | `R` | 6.4.3 적절한 링크 텍스트 (WCAG 2.4.6) | |
| 트리거 버튼과 툴팁을 `aria-labelledby`로 연결하여, 스크린 리더가 초점을 받을 때 내용을 읽게 합니다 | `G` | — (WCAG 1.3.1) | |
| 팝오버는 읽기 순서상 트리거 바로 뒤에 둡니다 | `R` | 5.3.2 콘텐츠의 선형구조 (KRDS: "콘텐츠의 선형화") | |

**키보드와 포인터**

| 이벤트 | 동작 |
|--------|------|
| 트리거에 Mouseover, Focus. 터치스크린에서는 Click | 툴팁을 표시합니다 |
| (트리거나 팝오버에서) Mouseleave, Blur. 터치에서는 바깥을 Click | 툴팁을 숨깁니다 |
| Esc | 툴팁을 숨기고 초점은 트리거에 유지하며, 초점이 벗어났다가 돌아올 때까지 숨긴 상태를 유지합니다 |

**마크업**: `.krds-tooltip`(트리거)과 `.krds-tooltip-popover`가 필수이며, 선택은 `.tooltip-vertical`(위 또는 아래)과 `.tooltip-box`(박스 스타일)입니다. 스크립트 `krds_tooltip`은 `data-tooltip`으로 팝오버를 만들어 `aria-hidden="true"`를 지정한 채 버튼 뒤에 삽입하고, 버튼에 `aria-labelledby`를 지정합니다.

```html
<button type="button" class="krds-btn icon krds-tooltip" data-tooltip="입력한 검색 조건을 모두 지웁니다">
  <span class="sr-only">검색 조건 초기화</span><i class="svg-icon ico-reset" aria-hidden="true"></i>
</button>
<!-- The kit names the button "button text + data-tooltip" through aria-labelledby: do not repeat the same text in both -->
```

- `D`: KRDS의 스크립트는 `mouseover`, `mouseout`(버튼에서만), `focus`, `focusout`만 등록합니다. 터치 Click, 포인터가 팝오버 위에 있는 동안 열린 상태 유지(WCAG 1.4.13), Esc로 숨긴 상태 유지는 구현되어 있지 않습니다. 키트를 사용할 때 이를 추가합니다.
- `D`: 트리거에 이미 텍스트 레이블이 있고 툴팁이 정보를 덧붙이는 경우, `aria-describedby`는 버튼 자신의 이름을 유지하지만 `aria-labelledby`(KRDS)는 이름을 대체합니다. KRDS의 스크립트는 이를 보완하려고 버튼 텍스트를 팝오버에 복사하며, KRDS를 따른다면 이 동작을 유지합니다.
