# 폼 패턴 (기본 패턴)

입력 폼에 쓰는 KRDS 기본 패턴인 입력 폼, 개인 식별 정보 입력, 오류, 동의, 첨부파일, 확인, 도움을 다룹니다. 모두 2025-01-15에 최초 등록되었습니다(Figma v1.0.0, HTML Component Kit v1.0.1).

각 패턴에는 **규칙** 표가 있습니다. `R`, `G`, `D`는 `SKILL_ko.md`에서 정의합니다. KWCAG 열은 KRDS가 인용한 KWCAG 2.2 항목과 그 번호이며, `—`는 KRDS가 KWCAG 항목을 인용하지 않았다는 뜻입니다.

## 입력 폼 (input form)

사용자가 데이터를 입력하여 서버로 전송하는 콘텐츠 섹션이며, 하나 이상의 입력 컨트롤로 구성됩니다.

**구조**: 1 제목(입력 폼의 목적), 2 설명(선택, 데이터를 입력할 때 유의할 사항), 3 콘텐츠(입력 컴포넌트), 4 필드셋(선택, 관련 컴포넌트를 묶음), 5 오류 메시지, 6 액션 버튼(제출 또는 중단).

**유형**

| 유형 | 사용하는 경우 |
|------|---------------|
| 단일 화면 | 기본 유형입니다. 점진적 공개법(progressive disclosure)으로 복잡성을 줄입니다 |
| 모달 | 매우 중요하고 자주 입력하거나 수정하지 않는 데이터에 사용합니다. 입력 컴포넌트는 5개 이내로 구성하는 것이 바람직합니다 |
| 단계별 | 데이터가 복잡하거나 중간 저장이 필요할 때 사용합니다. 단계가 명확해야 하고, 각 단계의 콘텐츠는 논리적이고 선형적인 관계를 가져야 하며, 진행 상황은 별도 컴포넌트(단계 표시기)로 보여 주어야 합니다. 숙달된 사용자에게는 비효율적이므로, 먼저 섹션을 더 명확하게 나누고 제목을 정확하게 달고 콘텐츠를 간결하게 만들어 봅니다. 질문은 쉬운 것에서 어려운 것 순으로, 의미 있는 작은 덩어리로 나눕니다 |

**검증**

폼은 필수 항목을 입력했는지, 값이 요구하는 양식에 맞는지 확인하고, 부적합한 입력에는 피드백을 제공해야 합니다(`R`).

| 이벤트 | 동작 |
|--------|------|
| 클라이언트 측 검증 | 권장합니다. 전송하기 전에 브라우저에서 확인하고, 오류가 있는 필드에 인라인 메시지를 표시합니다 |
| 서버 측 검증 | **반드시 함께 사용해야 합니다.** 클라이언트 검증은 쉽게 우회되고 보안 확인이 아닙니다. 결과는 필드에 인라인으로도 표시합니다 |
| Keyup | 실시간 피드백이 필요한 값(중복 불가 아이디, 작성 규칙이 있는 비밀번호)은 입력하는 동안 검증합니다 |
| Focusout | 값을 모두 입력하기 전에는 판단하기 어려운 값(날짜)은 사용자가 필드를 벗어날 때 검증합니다 |
| 제출 버튼 Click 또는 Enter (서버 측) | 오류가 발생한 **첫 번째** 필드로 초점을 이동합니다 |

- 규칙은 오류를 정확하게 식별하라고 요구하고 WCAG Status Messages를 인용하지만, 마크업은 제시하지 않습니다. `D`: 오류 메시지마다 `aria-describedby`로 해당 필드와 연결하고, `aria-invalid="true"`를 지정하며, 오류가 많다면 상단에 필드로 연결되는 링크가 있는 요약을 추가합니다.

## 개인 식별 정보 입력 (personal identification data)

특정 개인의 신원을 밝히거나 개인 또는 단체의 기본 정보를 확인하는 데 쓰이는 모든 정보입니다. KRDS는 이름, 생년월일, 성별, 전화번호 네 가지 필드를 다룹니다.

**규칙**

| 규칙 | 강도 | KWCAG | 검사 방법 |
|------|------|-------|-----------|
| 서비스에 필요한 정보인지 다시 한 번 확인합니다 | `R` | — | 모든 필드에 수집 목적이 명시되어 있는지 확인합니다 |
| 입력이 필요한 데이터의 용도를 명확하게 설명합니다 | `R` | — | |
| 모든 개인 식별 정보 필드에서 복사와 붙여넣기를 허용합니다 | `R` | — | `onpaste="return false"`가 없는지 확인합니다 |
| 기본값을 설정하지 않습니다. 플레이스홀더는 실제 입력과 쉽게 구분되어야 합니다 | `R` | — | |
| **이름**: 사용자가 입력할 수 있는 모든 문자(기호와 공백 포함)의 입력과 표시를 지원합니다. 본인인증처럼 과업에서 형식을 제한한다면 제약을 설명하고 대안을 제시합니다 | `R` | — | |
| **이름**: 모든 이름을 수용할 수 있는 글자 수를 허용하고, 최대 길이에 맞춰 필드 너비를 정합니다. 한글 이름에 3글자 이상을 요구하지 않습니다 | `R` | — | 두 글자 이름이 통과하는지 확인합니다 |
| **이름**: 단일 텍스트 필드를 사용합니다. 모든 이름이 성/이름 형식은 아니므로 이름 필드를 여러 개 두는 것은 신중하게 합니다. (입력 폼 패턴은 성과 이름을 한 행에 둘 수 있는 필드로 들었습니다. `D`: 더 구체적인 이 규칙을 따릅니다) | `R` | — | |
| **이름**: 개명한 사용자가 이름을 입력할 수 있는지 확인하고, 제약이 있다면 필드 주변에 해결 방안을 설명합니다 | `R` | — | |
| **로마자 이름(외국인)**: 필드 가로 길이를 최소 320~360px 이상으로 하거나, 단일 열 폼에서는 100%로 합니다. 긴 이름은 스크롤되거나 전체가 보여야 합니다 | `G` | — | |

| **전화번호**: 레이블을 명확하게 붙입니다(휴대 전화번호, 지역 번호. 유형이 중요하지 않으면 전화번호) | `G` | — | |

| **전화번호**: 국가 코드는 국가명과 코드 목록을 제공하는 콤보박스로 입력받습니다 | `G` | — | |

**KRDS가 다루지 않는 필드** (`D`)

KRDS는 주민등록번호, 주소, 이메일에 대한 규칙과 `autocomplete` 값을 제시하지 않습니다. 이 스킬은 다음을 추가하며, 검토할 때는 KRDS의 범위를 넘어선다고 밝힙니다.

| 필드 | `autocomplete` | 기타 속성 | 비고 |
|------|----------------|-----------|------|
| 이름 | `name` | | KRDS에 따라 필드 하나로 받습니다 |
| 생년월일(단일 필드) | `bday` | `inputmode="numeric"` | 필드가 여러 개이면 `bday-year`, `bday-month`, `bday-day`를 씁니다 |
| 휴대전화 또는 전화번호 | `tel`(국가 코드가 없으면 `tel-national`) | `type="tel"` | `type="tel"`은 전화번호 키패드를 띄웁니다 |
| 이메일 | `email` | `type="email"` | |
| 우편번호 | `postal-code` | `inputmode="numeric"`, 주소 검색으로 채우면 읽기 전용 | |
| 주소 | `address-line1`(도로명 주소), `address-line2`(상세 주소) | | 도로명 주소 검색을 여는 버튼으로 주소를 검색하고, 상세 주소는 별도 텍스트 필드로 둡니다 |
| 주민등록번호 | `off` | 뒷자리는 `type="password"` 또는 마스킹 | 법령이 구체적으로 요구하거나 허용하는 경우에만 수집하고, 다른 가입 방법(예: 본인 확인)을 제공하며, 저장할 때는 암호화합니다(개인정보 보호법 제24조의2. 이 스킬에서는 확인하지 않았으므로 law.go.kr에서 현행 조문을 확인합니다. `secure-coding` SR2-7) |
| 사용자 ID, 비밀번호 | `username`, `current-password` 또는 `new-password` | | `application-flow_ko.md`의 로그인 정보 입력을 참조합니다 |

<div class="form-group">

- `D`: KRDS의 성별 예시는 `div.form-tit`만 사용하고, KRDS의 라디오 버튼 페이지가 권장하는 `fieldset`/`legend`를 쓰지 않습니다(`selection-components_ko.md`). 이름 예시에도 `autocomplete`가 없어서 위의 규칙을 어깁니다.

## 오류 (error)

사용자가 요청한 작업을 시스템이 완료하지 못했을 때 표시합니다. 사전 안내인 경고와 달리 이미 발생한 문제를 알리며, 사용자가 본래 행동을 완수하도록 **유도해야** 합니다. 오류가 발생한 지점에 인라인으로 표시하거나 모달로 표시합니다.

**규칙**

| 규칙 | 강도 | KWCAG | 검사 방법 |
|------|------|-------|-----------|
| 크기, 색상, 위치로 오류를 빠르게 인지할 수 있게 표현합니다 | `R` | — | |
| 어떤 오류가 어느 지점에서 발생했는지 분명하게 설명합니다 | `R` | — | 메시지에 필드와 문제가 드러나는지 확인합니다 |
| 오류를 수정할 수 있는 방법을 제공합니다. 내용이 복잡하다면 특히 그렇습니다 | `G` | — | |
| 사용자를 안심시키는 정중한 문체를 사용합니다 | `R` | — | |
| 오류가 발생한 요소로 초점을 자동으로 이동합니다. 오류 모달을 닫은 뒤에는 오류가 발생한 필드로 초점을 이동합니다 | `R` | 7.3.1 오류 정정 | |
| 오류를 안내한 뒤에도 사용자의 입력값을 유지합니다 | `R` | 7.3.1 오류 정정 | |

**마크업**: 인라인 오류는 `.form-conts.is-error`와 `p.form-hint-invalid`를 사용합니다(`SKILL_ko.md`의 "공통 필드 마크업" 참조). KRDS는 인라인 메시지 대신 모달을 쓰는 시점을 밝히지 않습니다. `D`: 필드에 인라인 메시지를 표시하는 방식을 우선하고, 모달은 필드와 관련이 없는 오류(예: 제출 실패)에만 사용합니다. 오류 모달에는 `role="dialog"`, `aria-modal="true"`, `aria-labelledby`로 연결한 제목, 동작을 이름으로 하는 버튼 하나가 필요합니다(KRDS의 예시는 "아니요/예"를 쓰는데 오류에는 맞지 않습니다).

## 동의 (consent)

사용자가 이용 조건과 절차를 읽고 동의 여부나 안내 사항 확인 여부를 확인하게 합니다. 약관은 방대하고 어려운 용어로 쓰여 있으므로 알기 쉽게 **구조화해야** 합니다.

**구조**: 1 일괄 동의 옵션(a 체크박스: 전체 항목의 선택 상태를 전환, b 설명: 동의 항목 전체와 선택 동의 항목에 대한 정보), 2 목록(a 컨테이너, b 항목 제목, c 약관이 들어 있는 본문, d 라디오 버튼 또는 체크박스인 동의 옵션).

**규칙**

| 규칙 | 강도 | KWCAG | 검사 방법 |
|------|------|-------|-----------|
| "동의하지 않음" 옵션을 제공합니다 | `G` | — | 각 항목에 동의와 비동의가 모두 있는지 확인합니다 |
| 동의함과 동의하지 않음을 구분하기 쉽게 표현합니다 | `G` | — | |
| 필수 항목과 선택 항목을 구분합니다. 각 제목에 필수 또는 선택을 표시하고, 필수 항목은 상단에 모아 둡니다 | `R` | — | |
| 키보드로 약관을 스크롤할 수 있게 합니다 | `R` | 6.1.1 키보드 사용 보장 | 스크롤되는 약관 상자가 초점을 받을 수 있는지(`tabindex="0"`) 확인합니다 |
| 약관을 제목과 문단으로 구조화합니다 | `R` | 6.4.2 제목 제공 | |
| 라디오 레이블은 컨트롤의 오른쪽에 두고, 각 라디오를 `aria-describedby`로 해당 항목 제목과 연결합니다 | `R` | 7.3.2 레이블 제공 | 각 옵션의 설명에 해당 항목 이름이 드러나는지 확인합니다 |

**키보드와 동작**

| 조작 | 동작 |
|------|------|
| Tab, Shift + Tab | 포커스링을 표시하면서 다음 요소 또는 이전 요소로 이동합니다 |
| "전체 동의", Click 또는 Space | 선택하면 모든 항목이 동의함이 되고, 해제하면 모든 항목이 동의 안 함이 됩니다. 초점은 체크박스에 유지됩니다 |
| 하나라도 동의 안 함인 항목 | "전체 동의"는 해제된 상태를 유지해야 합니다 |
| 개별 항목 | 라디오 버튼과 체크박스의 규칙을 따릅니다 |

```html
<fieldset class="agree-item">
  <legend><h4 class="agree-tit" id="agree1_tit">[필수] 개인정보 수집 및 이용</h4></legend>
  <button type="button" class="krds-btn small secondary" aria-describedby="agree1_tit">약관 읽기</button>
  <div class="krds-check-area">
    <div class="krds-form-check"><input type="radio" name="agree1" id="agree1_n" aria-describedby="agree1_tit"><label for="agree1_n">동의하지 않음</label></div>
    <div class="krds-form-check"><input type="radio" name="agree1" id="agree1_y" aria-describedby="agree1_tit"><label for="agree1_y">동의함</label></div>
  </div>
</fieldset>
```

- `D`: KRDS의 예시는 옵션에 `aria-describedby`가 없고, `fieldset`/`legend`가 없으며, 똑같은 "약관읽기" 버튼이 네 개이고, 선택 항목이 동의/비동의 대신 "확인함" 체크박스 하나입니다. 바로잡은 예시는 규칙을 따릅니다.
- `D`: KRDS는 필수 항목에 동의하지 않았을 때 어떻게 처리하는지 밝히지 않습니다. 다음 단계로 넘어가지 못하게 막고, 해당 항목에 인라인 오류를 표시합니다(오류 참조).

## 첨부파일 (attachments)

게시물이나 본문에 첨부된, 내려받을 수 있는 파일입니다. 이 패턴은 다운로드 패턴이며, 업로드는 `input-components_ko.md`(파일 업로드)에 있습니다.

**구조**: 1 파일 이름, 2 파일 정보(유형, 크기, 페이지 수), 3 다운로드 링크, 4 미리 보기 링크(새 탭에서 열림), 5 컨테이너, 6 아이콘(선택).

**유형**: 인라인 링크(본문 안), 목록 링크(다운로드와 미리 보기 링크를 둔 별도 컨테이너이며 상세 정보가 있는 문서에 사용), 아이콘 링크(구조화된 목록과 표 안).

**규칙**

| 규칙 | 강도 | KWCAG | 검사 방법 |
|------|------|-------|-----------|
| 링크를 누르면 파일이 내려받아진다는 점을 사전에 안내합니다(주변이나 링크 안에 다운로드라는 단어를 넣습니다). 그래야 동작을 예측할 수 있습니다 | `R` | — | |
| 파일 유형과 크기를 파일 이름의 오른쪽에 `[유형, 크기]` 형식으로 표시하고, 크기 단위는 KB, MB, GB를 사용합니다 | `G` | — | `[hwp, 328KB]` |
| 인라인 첨부파일의 텍스트는 주변 텍스트와 같은 크기로 표시합니다 | `R` | — | |
| 첨부파일 아이콘의 대체 텍스트는 정확한 파일 이름으로 제공합니다 | `R` | 5.1.1 적절한 대체 텍스트 제공, 6.4.3 적절한 링크 텍스트 | |
| 첨부된 문서 자체도 스크린 리더가 읽을 수 있는 형식(텍스트이며, 이미지에는 대체 텍스트 포함)으로 제공합니다 | `R` | — | |

```html
<li>
  <p class="tit" id="file1">사회보장급여 신청(변경)서 [hwp, 328KB]</p>
  <div class="btn-wrap">
    <a href="/files/1.hwp" class="krds-btn medium text" download aria-describedby="file1">다운로드</a>
    <a href="/files/1/view" class="krds-btn medium text" target="_blank" aria-describedby="file1">바로보기<span class="sr-only">(새 창)</span></a>
  </div>
</li>
```

- `D`: KRDS의 예시는 다운로드와 미리 보기에 `<button>`을 쓰고 이름이 "다운로드"뿐이어서, 파일이 여러 개이면 똑같은 버튼이 여러 개가 됩니다. 다운로드와 미리 보기는 이동이므로 링크를 사용하고, 파일 이름을 포함하거나 연결합니다.

## 확인 (confirmation)

사용자의 행위가 쉽게 취소할 수 없는 결과로 이어지거나, 사용자가 그 효과를 인지해야 할 때 사용합니다. 유형은 폼을 제출할 때와 화면의 중요한 맥락이 변경될 때입니다.

**규칙**

| 규칙 | 강도 | KWCAG | 검사 방법 |
|------|------|-------|-----------|
| 심각하거나 취소하기 어려운 행동에만 확인을 요청합니다. 확인을 자주 요청하면 사용자가 중요한 확인을 무시하게 됩니다 | `R` | — | |
| 상황을 명확하고 간결하게 설명합니다. 어떤 결과가 발생하는지와 왜 중요한지를 적습니다 | `R` | — | |
| 확정 버튼과 취소 버튼을 모두 제공합니다 | `R` | — | |
| 본문을 읽지 않아도 어떤 일이 일어나는지 알 수 있도록 버튼 레이블에 행동을 설명합니다("확인"이 아니라 "신청 취소") | `G` | — | |

- KRDS는 이 패턴에 접근성 규칙을 제시하지 않으며, 예시는 "취소/확인" 버튼이 있는 약관 모달입니다. `D`: 확인 모달에는 `role="dialog"`(또는 `alertdialog`), `aria-modal="true"`, 열릴 때 대화상자 안으로 이동하고 닫힐 때 호출한 컨트롤로 되돌아오는 초점, 동작을 이름으로 하는 레이블이 필요합니다.

## 도움 (help)

UI의 작동 방식, 사용 방법, 과업 흐름에 관한 도움말이며, 여러 컴포넌트를 조합하여 제공합니다.

**유형**

| 유형 | 컴포넌트 | 사용하는 경우 |
|------|----------|---------------|
| 고정형 도움말(항상 표시) | 안내 영역(섹션 제목과 설명), 레이블, 인라인 텍스트, 플레이스홀더 | 모든 사용자가 확인해야 하는 정보. 자주 사용하는 사용자와 익숙한 화면 |
| 사용자 요청에 의한 도움말 | 툴팁, 맥락적 도움말, 도움 패널, 코치마크, 따라하기 패널 | 문제를 예방할 때. 신규 사용자, 복잡한 서비스, 새로운 기능 |
| 반응형 도움말 | 자주 묻는 질문, 도움말 메뉴(별도 화면) | 이미 문제를 겪고 있는 사용자 |

**규칙**

| 규칙 | 강도 | KWCAG | 검사 방법 |
|------|------|-------|-----------|
| 과업에 맞는 도움말을 제공합니다. 단순하거나 익숙한 화면에는 고정형, 복잡하거나 새로운 화면에는 사용자 요청형이 좋습니다 | `G` | — | |
| 도움말은 명확하고 간결하게, 사용자의 관점에서 적시에 작성합니다 | `R` | — | |
| 일부 이용 환경에서만 참고할 수 있는 도움말은 작성하지 않습니다 | `R` | — | |
| 사용자 요청에 의한 도움말의 내용은 반응형 도움말(자주 묻는 질문, 도움말 메뉴)로도 이용할 수 있게 합니다 | `R` | — | |
| 같은 페이지 제목과 버튼 이름은 모든 서비스에서 같은 단어로 지칭합니다 | `R` | — | |
| 관련 화면이나 리소스로 연결되는 링크는 새 탭에서 엽니다 | `R` | — | |
| **안내 영역**: 본문 전체를 이해하는 데 필요한 정보(취소나 수정 가능 여부, 전자서명이나 본인인증 절차, 제출할 증빙서류)에 사용하고, 본문 상단에 배치하며, 한 화면에 하나만 둡니다. 추가 내용은 접힌 상태의 디스클로저에 넣고, 반드시 확인해야 하는 정보는 넣지 않습니다 | `R` | — | |
| **플레이스홀더**: 레이블이나 도움말의 대체 수단으로 사용하지 않습니다. 날짜나 숫자의 형식, 자릿수를 보여 줄 수 있으며, 같은 텍스트를 인라인 텍스트로도 제공해야 합니다 | `R` | — | 모든 플레이스홀더 텍스트가 눈에 보이는 도움말에 반복되는지 확인합니다 |
| **인라인 텍스트**: 과업을 완료하는 데 필요한 정보를 요소 옆에 제공합니다 | `G` | — | |
| **툴팁**: 짧은 추가 정보(한두 단어, 한 문장)와 아이콘만 있는 컨트롤의 레이블에 사용합니다 | `G` | — | |
| **맥락적 도움말**: 컴포넌트의 상태나 상세 정보에 사용합니다 | `G` | — | |
| **도움 패널**: 분량이 많은 도움말이나 복잡한 과업(과업 수행 결과, 필드가 필요한 이유, 결정하는 방법, 입력 방법, 정의)에 사용합니다 | `G` | — | |
| **코치마크, 따라하기 패널**: 이용 빈도가 낮고 단계가 많은 과업에 사용합니다 | `G` | — | |

- KRDS의 도움 예시는 링크와 닫기 버튼이 있는 맥락적 도움말 팝오버에 `role="tooltip"`을 붙입니다. 바로잡은 마크업은 `action-help_ko.md`를 참조합니다.
