# 4. 견고성 (Robust)

콘텐츠는 현재와 미래의 보조기술에서 안정적으로 동작해야 합니다.

`KWCAG` 열은 KS X OT0003:2022의 항목 번호입니다. 번호가 있는 행은 `수준`과 관계없이 한국 웹 접근성을 준수하기 위한 **필수** 항목입니다. `—`는 대응하는 KWCAG 항목이 없다는 뜻입니다.

## 4.1 문법 준수 (Markup Compliance)

참고: WCAG 2.2에서는 SC 4.1.1 Parsing이 삭제되었지만, KWCAG 8.1.1은 여전히 아래 항목들을 검사하도록 요구합니다.

| ID | 규칙 | 검사 방법 | 범위 | 수준 | KWCAG |
|----|------|-----------|------|------|-------|
| 4.1.1 | 요소의 여는 태그와 닫는 태그가 짝을 이루어야 합니다(명세에서 생략을 허용하는 경우는 예외입니다) | HTML 유효성을 검사하여 닫히지 않았거나 짝이 맞지 않는 태그가 없는지 확인합니다 | W | A | 8.1.1 |
| 4.1.2 | 요소는 올바르게 중첩되어야 하며, 서로 엇갈리면 안 됩니다 | HTML 유효성을 검사하여 잘못 중첩된 요소가 없는지 확인합니다(예: `<b><i></b></i>`) | W | A | 8.1.1 |
| 4.1.3 | 하나의 요소 안에 같은 속성을 중복해서 선언하지 않습니다 | HTML 유효성을 검사하여 각 속성이 요소마다 한 번씩만 나타나는지 확인합니다 | W | A | 8.1.1 |
| 4.1.4 | 하나의 문서 안에서 id 값이 중복되면 안 됩니다 | HTML 유효성을 검사하여 페이지 안의 모든 id 값이 고유한지 확인합니다 | W | A | 8.1.1 |

## 4.2 보조기술 호환성 (Assistive Technology Compatibility)

| ID | 규칙 | 검사 방법 | 범위 | 수준 | KWCAG |
|----|------|-----------|------|------|-------|
| 4.2.1 | 사용자 인터페이스 구성요소는 올바른 이름, 역할, 상태, 값을 보조기술에 전달해야 합니다. 네이티브 요소나 올바른 ARIA 역할을 사용합니다 | 스크린 리더가 각 컨트롤을 올바른 이름, 역할, 상태(checked, expanded 등)와 함께 읽어 주는지 확인합니다 | WM | A | 8.2.1 |
| 4.2.2 | 웹 애플리케이션과 플러그인은 플랫폼 접근성 API(MSAA, UI Automation, IAccessible2, AXAPI 등)를 사용해야 하며, 새로 추가한 기능도 이 API에 이름, 역할, 상태, 값을 전달해야 합니다. 국내 보조기술로 접근할 수 없는 웹 애플리케이션은 피해야 하며, 불가피하게 사용한다면 접근 가능한 대체 수단을 제공해야 합니다 | 스크린 리더로 테스트하여 모든 커스텀 위젯을 조작할 수 있고 올바르게 읽히는지 확인합니다 | W | A | 8.2.1 |
| 4.2.3 | 중요한 상태 메시지(검색 결과 개수, 장바구니 변경, 로딩 상태, 인라인 오류)는 초점을 옮기지 않고도 보조기술이 읽어 주어야 합니다 | 상태 변화를 일으킨 뒤, 초점이 이동하지 않은 상태에서 스크린 리더가 그 내용을 읽어 주는지 확인합니다(role="status", aria-live, role="alert" 사용) | WM | AA | — |
